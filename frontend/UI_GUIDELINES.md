# Frontend UI Guidelines

> 前端视觉开发规范

> 适用范围：`frontend/` 下所有 Vue 页面、组件及 Element Plus 样式。
>
> 视觉定位：深蓝灰、商务、稳重、清晰、适合长时间办公。
>
> 本规范是新增页面、改造页面和 AI 辅助编码时的默认视觉约束。若业务需求没有明确指定其他样式，必须遵循本规范。

## 1. 核心原则

1. 使用深蓝灰作为品牌主色，不使用蓝紫渐变。
2. 页面主体保持灰白中性色，主题色只用于关键操作、选中状态和品牌区域。
3. 状态颜色只表达业务语义，不用主题色替代成功、警告或错误状态。
4. 优先复用全局变量和公共组件，页面内不得重复定义一套近似色值。
5. 信息密度可以较高，但必须通过间距、分组和文字层级保持可读性。
6. 装饰服务于信息表达，不使用无业务意义的强渐变、发光和大面积彩色背景。

## 2. 主题色板

### 2.1 品牌与界面颜色

| 语义 | CSS 变量 | 色值 | 用途 |
| --- | --- | --- | --- |
| 主色 | `--color-primary` | `#334155` | 主按钮、链接、激活项、关键进度 |
| 主色悬停 | `--color-primary-hover` | `#1E293B` | 主按钮悬停、链接悬停 |
| 主色按下 | `--color-primary-active` | `#0F172A` | 按钮按下、深色强调 |
| 主色浅底 | `--color-primary-soft` | `#E2E8F0` | 标签、头像、选中行、浅色提示 |
| 页面背景 | `--color-page-bg` | `#F8FAFC` | 页面主背景 |
| 卡片背景 | `--color-surface` | `#FFFFFF` | 卡片、弹窗、表单容器 |
| 次级背景 | `--color-surface-muted` | `#F1F5F9` | 表头、分组、禁用区域 |
| 主文字 | `--color-text-primary` | `#111827` | 标题、正文、关键数据 |
| 次级文字 | `--color-text-secondary` | `#475569` | 描述、表格普通内容 |
| 弱化文字 | `--color-text-muted` | `#64748B` | 提示、时间、辅助信息 |
| 边框 | `--color-border` | `#E2E8F0` | 卡片、输入框、表格分隔线 |
| 深色侧栏 | `--color-sidebar` | `#1E293B` | 左侧导航栏 |
| 侧栏深色 | `--color-sidebar-deep` | `#0F172A` | 侧栏渐变终点或底部区域 |

### 2.2 业务状态颜色

| 状态 | 色值 | 使用场景 |
| --- | --- | --- |
| 成功 | `#16A34A` | 已完成、已通过、正常 |
| 警告 | `#D97706` | 即将到期、待确认、风险 |
| 错误 | `#DC2626` | 失败、逾期、删除、异常 |
| 信息 | `#0284C7` | 普通通知、说明、处理中 |

业务状态颜色只能在状态标签、提示图标、进度信息和危险操作中使用，不得大面积铺满页面。

## 3. 推荐的全局变量

主题变量应集中维护，建议放入 `frontend/src/styles/theme.css`，禁止散落在各业务页面中。

```css
:root {
  --color-primary: #334155;
  --color-primary-hover: #1e293b;
  --color-primary-active: #0f172a;
  --color-primary-soft: #e2e8f0;

  --color-page-bg: #f8fafc;
  --color-surface: #ffffff;
  --color-surface-muted: #f1f5f9;
  --color-border: #e2e8f0;

  --color-text-primary: #111827;
  --color-text-secondary: #475569;
  --color-text-muted: #64748b;

  --color-sidebar: #1e293b;
  --color-sidebar-deep: #0f172a;

  --color-success: #16a34a;
  --color-warning: #d97706;
  --color-danger: #dc2626;
  --color-info: #0284c7;

  --radius-sm: 6px;
  --radius-md: 8px;
  --radius-lg: 12px;
  --radius-xl: 16px;

  --shadow-card: 0 8px 24px rgba(15, 23, 42, 0.05);
  --shadow-dropdown: 0 12px 32px rgba(15, 23, 42, 0.12);
}
```

## 4. 页面框架

### 4.1 左侧导航

- 默认背景使用 `#1E293B`。
- 允许使用 `linear-gradient(180deg, #1E293B 0%, #0F172A 100%)` 的轻微同色系渐变。
- 普通菜单文字使用 `rgba(255, 255, 255, 0.72)`。
- 菜单悬停背景使用 `rgba(255, 255, 255, 0.08)`。
- 激活菜单使用 `#334155`；为提高层次，可加浅阴影，但不得发光。
- Logo 区使用 `#334155` 或比侧栏略浅的深蓝灰，不使用亮蓝和蓝紫。
- 菜单项圆角为 `8px`，高度建议为 `44px` 至 `50px`。

### 4.2 顶部导航

- 背景使用白色。
- 下边框使用 `#E2E8F0`。
- 高度建议为 `60px` 至 `64px`。
- 面包屑和次要操作保持中性灰，不要全部染成主色。
- 用户头像可使用 `#E2E8F0` 浅底和 `#334155` 文字。

### 4.3 主内容区

- 页面背景统一使用 `#F8FAFC`。
- 桌面端外边距建议为 `24px`，小屏幕使用 `16px`。
- 页面区块间距建议为 `16px`、`20px` 或 `24px`，不得出现无规律间距。
- 内容宽度不足时优先调整网格和换行，不通过缩小字号强行容纳。

## 5. 组件规范

### 5.1 按钮

- 每个页面只能有一个视觉权重最高的主操作区域。
- 主按钮使用深蓝灰底色和白色文字。
- 次要操作使用默认按钮、文字按钮或浅灰按钮。
- 删除、作废等危险操作使用红色，但不得默认占据最高视觉权重。
- 同一区域按钮高度、圆角和图标尺寸必须一致。
- 禁止使用蓝紫渐变按钮、霓虹阴影和高饱和发光效果。

### 5.2 卡片

- 背景使用白色，边框使用 `#E2E8F0`。
- 常规圆角使用 `12px`，数据概览卡可使用 `16px`。
- 默认阴影使用 `--shadow-card`，避免厚重悬浮效果。
- 卡片之间优先通过间距分隔，不依赖不同背景色堆叠。
- 卡片标题建议为 `16px` 至 `18px`、字重 `600`。

### 5.3 表格

- 表头使用 `#F8FAFC` 或 `#F1F5F9`。
- 表头文字使用次级文字色，避免纯黑粗体。
- 表格边框使用 `#E2E8F0`。
- 行悬停使用 `#F8FAFC`。
- 选中行使用主色浅底 `#E2E8F0`，不要使用高饱和蓝色。
- 状态列优先使用语义标签，不用纯文字颜色作为唯一标识。
- 操作列保持紧凑，危险操作与普通操作之间要有明确区分。

### 5.4 表单

- 默认使用上方标签或统一宽度的左侧标签，不在同一表单中混用。
- 输入框圆角使用 `8px`。
- 聚焦边框使用 `#334155`，聚焦阴影应轻微。
- 必填项、校验错误和帮助文字必须明确，不仅依靠颜色区分。
- 长表单必须分组，可使用卡片、分区标题、标签页或折叠面板。
- 弹窗内表单需控制宽度；字段较多时优先使用抽屉或全屏编辑页。

### 5.5 标签与状态

- 普通分类标签使用深蓝灰浅底。
- 成功、警告、错误和信息状态使用对应语义色。
- 标签圆角建议为 `6px`，不默认使用过度圆润的胶囊样式。
- 同一业务状态在不同页面必须保持相同颜色和文字。

### 5.6 数据看板

- 顶部横幅允许使用深蓝灰同色系渐变：

```css
background: linear-gradient(135deg, #0f172a 0%, #334155 100%);
```

- 横幅只出现在概览页或重点入口，不要在每个业务页面重复使用。
- 数据卡的主题色只用于左边框、顶部细线、图标或小面积强调。
- 图表颜色优先采用低饱和、可区分的序列，避免整套图表都使用近似蓝紫色。

## 6. 字体、圆角与阴影

### 字体层级

| 类型 | 建议字号 | 字重 |
| --- | --- | --- |
| 页面主标题 | `28px` 至 `36px` | `600` 或 `700` |
| 区块标题 | `18px` 至 `20px` | `600` |
| 卡片标题 | `16px` 至 `18px` | `600` |
| 正文 | `14px` | `400` |
| 辅助文字 | `12px` 至 `13px` | `400` |
| 关键数字 | `28px` 至 `36px` | `600` 或 `700` |

正文默认使用：

```css
font-family: Inter, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;
```

### 圆角

- 输入框、小按钮、菜单项：`6px` 至 `8px`。
- 卡片、弹窗：`12px`。
- 数据概览卡、特殊横幅：最大 `16px`。
- 不使用所有元素统一 `20px` 以上的大圆角。

### 阴影

- 阴影颜色以 `rgba(15, 23, 42, ...)` 为基础。
- 普通卡片阴影透明度不超过 `0.08`。
- 下拉框、弹窗可使用更明显阴影，但不得出现彩色发光。

## 7. 动效规范

- 常规过渡时间使用 `160ms` 至 `240ms`。
- 页面切换动画最长不超过 `300ms`。
- 只对颜色、透明度、位移和阴影做轻量过渡。
- 按钮悬停最多上移 `1px`，常规后台页面也可以不位移。
- 禁止循环漂浮、持续闪烁、背景粒子和无业务意义的动画。
- 必须兼容 `prefers-reduced-motion: reduce`。

## 8. 可访问性与可用性

- 正文与背景的对比度至少满足 WCAG AA。
- 不得只使用颜色表达状态，必须同时提供文字、图标或形状。
- 可点击元素必须有明确的悬停和键盘聚焦状态。
- 常规点击区域建议不小于 `36px × 36px`。
- 表格、表单和弹窗必须支持键盘操作。
- 禁用状态必须可辨认，但文字不能淡到无法阅读。

## 9. AI 编码强制规则

AI 新增或修改前端代码时，必须遵循以下顺序：

1. 先检查是否已有可复用的页面、组件、公共类和主题变量。
2. 优先使用 Element Plus 组件和现有公共组件。
3. 所有品牌色从 CSS 变量获取，不在业务组件中新增近似蓝灰色。
4. 业务状态使用统一的成功、警告、错误、信息颜色。
5. 新页面必须覆盖加载、空数据、错误、禁用和无权限状态。
6. 新增样式必须检查桌面端和窄屏布局。
7. 修改完成后运行 `npm run build`。
8. 涉及核心交互时，应在浏览器中检查真实渲染效果。

### AI 输出代码时禁止

- 使用 `#6366F1`、`#8B5CF6` 等蓝紫配色作为主题色。
- 创建蓝紫、彩虹或霓虹渐变。
- 在页面中复制一套新的主题色常量。
- 为普通卡片添加厚重阴影或发光边框。
- 为了“高级感”随意增加毛玻璃、背景光斑和漂浮动画。
- 用大面积绿色、红色或橙色替代中性页面背景。
- 在同一页面混用多种圆角、阴影和按钮风格。
- 未检查现有公共样式就直接重写 Element Plus 组件。

## 10. 页面验收清单

提交前逐项检查：

- [ ] 主色为深蓝灰，没有蓝紫渐变。
- [ ] 页面背景、卡片、边框和文字层级符合主题色板。
- [ ] 主要操作与次要操作的视觉权重明确。
- [ ] 成功、警告、错误和信息状态颜色使用正确。
- [ ] 页面内没有无必要的硬编码品牌色。
- [ ] 表格、表单、弹窗的间距和圆角一致。
- [ ] 加载、空数据、错误和无权限状态完整。
- [ ] 文字对比度足够，状态不只依靠颜色表达。
- [ ] 窄屏下不存在明显溢出、遮挡或无法操作的问题。
- [ ] `npm run build` 通过。

## 11. 当前系统改造建议

现有页面迁移到本规范时，建议按以下顺序进行：

1. 新建全局 `theme.css` 并映射 Element Plus 主题变量。
2. 改造主框架的 Logo、侧栏、激活菜单、顶部导航和页面背景。
3. 统一主按钮、链接、输入框聚焦和分页选中状态。
4. 改造数据看板横幅及数据卡强调色。
5. 搜索并替换各页面中散落的 `#3B82F6`、`#2563EB`、蓝色渐变和蓝色阴影。
6. 逐页检查业务状态色，避免将状态色错误替换成主题色。
