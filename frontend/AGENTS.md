# 前端协作约定

本目录及其子目录的前端开发除遵循仓库根目录 `AGENTS.md` 外，还必须遵循以下约定。

## 表格字段漏斗筛选范式

- 列表字段需要按列筛选时，字段名右侧统一使用公共组件 `src/components/common/ConfiguredColumnHeaderFilter.vue` 提供的漏斗按钮；不得在页面中复制漏斗图标、Popover、筛选状态样式或定位逻辑。
- 漏斗按钮必须紧邻字段名。未启用筛选时使用中性图标，启用后使用公共组件的高亮状态；不得为同一字段在查询栏中额外增加重复的筛选按钮或选择框。
- `type: 'select'` 且未显式设置 `multiple: false` 的字段统一视为多选筛选。打开漏斗后直接展示全部复选项，不得再嵌套需要二次点击的 Select 下拉框。
- 多选内容先写入临时值，用户可以连续勾选；面板提供“全选”“清空”“取消”“确定”和已选数量。“确定”后才更新正式筛选值、关闭面板并执行查询。
- 点击“取消”或面板外部只关闭面板，不提交临时选择；再次打开时必须从当前已生效的筛选值重新初始化。
- “清空”只清除面板内临时选择，点击“确定”后恢复该字段的完整列表；页面级“重置”仍统一清除所有常用和高级筛选。
- 复选项较多时只允许漏斗面板内部滚动，面板最大高度必须受视口限制，不得撑高表格或页面。
- 可选项超过 8 个且字段未设置 `filterable: false` 时，公共组件自动显示面板内搜索；存在搜索词时“全选”只合并当前匹配结果，不得误选隐藏选项。
- `type: 'text'` 继续遵循 400ms 防抖、回车查询、请求取消和旧响应保护；日期范围和明确设置 `multiple: false` 的单选字段保留与其输入语义匹配的控件。
- 新增表头筛选时，只需在页面筛选字段定义中声明 `type`、`options`、`multiple`、`headerWidth` 等配置并复用公共组件。除非先扩展公共组件，不得在业务页面实现特例交互。
- 新增或修改漏斗筛选后，必须验证：漏斗位置、激活态、连续多选、全选、清空、取消、点击外部、确定查询、页码重置、面板内部滚动以及其他字段筛选不受影响。
