# 云端数据库自动备份

两台应用服务器共用 `43.132.156.72:15432/xinshi_system`。备份只在运行 PostgreSQL 的云服务器上执行，容器为 `xinshi_prod_postgres`。每天香港时间 03:00 在线导出一次，主机关机错过任务时由 systemd 在下次启动后补跑。

## 留存与保护

- 备份目录为 `/var/backups/xinshi_system/postgres`，由 root 管理，权限 0700。每个时间戳目录包含 `xinshi_system.dump` 和 `SHA256SUMS`。
- 上限为最近 14 份，容量目标为 100 GiB，磁盘预留 50 GiB。超过数量或容量目标时，在新备份通过检查后从最旧的自动备份开始清理，并优先保留最近两份。空间不足或导出失败时保留已有备份，详情见服务日志。
- 归档包含数据库结构和数据，以及存入数据库的业务截图。完整应用恢复还需要独立保管资料卷、文件附件、应用配置和密钥。恢复到全新 PostgreSQL 实例前核对源端所用扩展、对象所有者、角色和表空间。数据库和备份同盘，云盘故障可能同时丢失两者。

## 安装与运行检查

在已获授权的云端运维会话核对主机名、部署目录、Git 提交、PostgreSQL 容器和库名，检查磁盘和既有任务。由受信任的部署目录执行以下命令。首次运行选在低峰，并避开结构变更窗口。

```bash
sudo install -m 0755 deploy/backup_cloud_db.sh /usr/local/sbin/xinshi-db-backup
sudo install -m 0644 deploy/xinshi-db-backup.{service,timer} /etc/systemd/system/
sudo systemd-analyze verify /etc/systemd/system/xinshi-db-backup.{service,timer}
sudo systemctl daemon-reload
sudo systemctl start xinshi-db-backup.service
sudo journalctl -u xinshi-db-backup.service -n 30 --no-pager
sudo systemctl enable --now xinshi-db-backup.timer
systemctl list-timers xinshi-db-backup.timer
```

备份服务是一次性任务，成功完成后通常为 `inactive (dead)`。结合日志中的“备份完成”、最近时间戳目录和定时器的下次执行时间确认状态。失败时查看 `systemctl status xinshi-db-backup.service` 和日志，排除原因后可手动执行同一个服务。暂停后续自动备份使用 `sudo systemctl disable --now xinshi-db-backup.timer`，已有备份继续保留。

## 恢复演练

1. 选择一份归档，在其所在目录运行 `sudo sha256sum -c SHA256SUMS`。安排低峰演练并核对容量。
2. 在同一云服务器准备独立的 PostgreSQL 18 实例和空库，使用独立容器、独立存储、无对外网络和无端口映射。核对恢复端容器名及数据库名，避免误指向生产容器。
3. 对隔离目标运行 `pg_restore --exit-on-error --single-transaction -d restore_check`，输入选定归档。检查客户、标注项目、截图记录及图片内容、关键序列，记下结果和耗时。校验和与目录检查用于定位归档问题，实际恢复才能验证数据能否还原。
4. 演练后删除本次隔离容器和临时数据，保留原备份。复核定时器与最近成功记录。
