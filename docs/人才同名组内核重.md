# 同名组内身份核对

姓名组是检索范围，不代表同一个人。两个字中文名、单词英文名和其他同名组都可以在工作台中逐对核对；此前按姓名长度执行的整组合并规则未扩大。

## 工作台

- 初始不选择任何档案。子组卡片可对照、调整成员、选择保留档案并单独预览；同一档案不能同时存在于两个草稿子组。
- 推荐子组内部每一对都必须有仍有效的高置信度同一人建议，且没有身份冲突。链式或重叠候选不强行划分；可在矩阵中逐对核对后人工选择。
- 单独保留只表示没有进入合并子组，其身份仍可能待核。没有匹配联系方式、语言不同或资料互补均不能直接证明不同人。
- “确认这两条不同人”仅用于两条档案。“预览确认不同人”用于两个子组，只区分交叉记录对，不区分任一子组内部记录。提交前列明全部记录对。
- 所有写入仍须超级管理员明确确认。Agent 建议不是人工结论，也不会触发自动归档。操作历史保留采用的报告标识、判断原文、所选成员及人工字段决策。
- 原编号、合并前后快照、字段来源、只读归档来源、继承附件和历史业务关联继续使用已有留存与撤销机制。

## 当前 Agent 离线初筛

不接外部模型网关，也不把聊天 Agent 当作后端可调用的模型服务。由当前会话读取证据、逐对形成判断，再导入报告；页面读取报告，不调用模型且不轮询。

在本机 PC、项目目录中使用项目虚拟环境，只读分批导出：

```powershell
.\.venv\Scripts\python.exe tools/export_talent_agent_review.py --output .tmp/talent-identity-review --page-size 5 --interval 2
```

同一目录可断点继续，已完成导出不自动重新扫描。需要新快照时使用新目录；检查点的数据库目标或证据规则不兼容时拒绝续扫。输出含个人资料，保留在忽略目录中，不提交 Git。

每批只使用一个独立连接，事务为只读，结束后释放连接。查询超时 3 秒、锁等待 200ms、空闲事务超时 5 秒。其他客户端连接达到 40、活跃查询达到 5、空闲事务达到 3，或存在超过 15 秒的事务时暂停；不自动重试。`paused.json` 保存 UTC+8 时间和可用的负载统计。

`input.json` 保存快照和资料指纹；`evidence.jsonl` 保留索引、联系方式匹配类型及共用数量、相同/冲突/互补资料，去掉联系方式明文和原附件链接。个人联系信息包含归档来源；公司“所在微信”不作为个人账号。

当前 Agent 对已读取的记录对生成如下判断文件；不确定的内容必须保留不确定，不能默认同一人：

```json
{
  "reviewer": "当前 Agent",
  "scope_note": "实际读取的资料范围及限制",
  "pairs": [
    {"index": [0, 0], "classification": "uncertain", "confidence": "low", "reason": "仅姓名相同，缺少身份依据", "cautions": []}
  ]
}
```

`classification` 为 `same`、`different`、`uncertain`；`confidence` 为 `high`、`medium`、`low`，表示证据分档，不是概率。未提供明确逐对判断的条目保留为未初筛，不假称 Agent 已识别。

```powershell
.\.venv\Scripts\python.exe tools/build_talent_agent_review_report.py --source .tmp/talent-identity-review/input.json --decisions .tmp/talent-identity-review/decisions.json
```

报告输出至 `outputs/talent-agent-review/latest.json`，原子替换，不修改业务数据库。新版报告按参与人员指纹和逐对证据版本验证；部分合并后不相关的建议继续保留，新成员产生新的待核关系。联系方式共用范围或归档来源联系信息变化会使受影响建议失效。旧版报告仍采用原来的整组失效规则。
