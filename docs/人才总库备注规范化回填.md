# 人才总库备注规范化回填

工具为 `tools/normalize_talent_remarks.py`，规则为 `tools/talent_remark_rules.py`。
只处理已有档案，不新增、合并或删除人才，不修改专业能力、报价、测试结果及操作人。
运行环境与生产授权遵守 `AGENTS.md`、`docs/infra.md` 和外部表导入规范。

## 字段映射

| 原备注内容 | 承接方式 |
| --- | --- |
| 明确的中文姓名、英文姓名、昵称 | 同名字段仅补空值；姓名、译员名字用于身份核验 |
| 邮箱、电话、微信、WhatsApp、Skype、Line | 受权限保护的联系字段；主/备用字段已占用时只使用空的其他联系字段 |
| 国籍、民族、性别、主要成长地、祖籍、现居地 | 对应个人字段；通讯录“地址”用途不明确时不作为现居地 |
| 年龄、出生日期、出生年月 | 仅承接完整明确值；不由年龄推算出生年月，不由年龄段推算年龄 |
| 来源、所在微信、所在微信群、简历路径 | 同名业务字段；不以原表开拓负责人代替系统操作人 |
| 职业状态、职业说明、明确项目经验 | 对应枚举或经历字段；不自动启用专业能力 |
| 最高学历、学校、专业、毕业年份、辅修、学位 | 已有唯一匹配经历补空值；信息明确且未有经历时创建子记录 |
| 明确母语、外语、方言/民族语言 | 关联有效语种目录；通用语种优先，多语种逐个识别 |
| 明确方言熟悉程度 | 同来源且行号一致的问卷值，补充唯一对应既有语言的空熟悉程度；不改变语言角色 |
| 明确证书及等级 | 自报证书记录，材料收到状态保持否；同义证书名称去重 |
| 单价、联系进度、评价、含糊语种及其他原文 | 保留备注并出具待核/保留/未对应理由 |

剥离值末尾明确的 `【第 X 行】` 等来源标签时，原文与标签继续保存在备注及计划中。
JSON 仅使用姓名明确对应的来源；历史差异、旧值、操作人账号不用于当前人才回填。
老通讯录“任务标签 + 姓名 + 任务标签（地区）”仅在已有完整姓名、固定任务词/语种目录和原始名称一致时认可身份；不做姓名模糊匹配。

成功承接的联系信息在备注中替换为“（已转入联系字段）”。替换不更改 JSON 键名、来源结构及未承接内容，原文保存在受限备份。目标字段已有“未知”“无”等占位文字也作为非空值保护，不静默覆盖。
数字型 JSON 电话仅在联系键或明确电话容器中替换，非联系数字保留；字符串账号紧邻中文说明时仍可按完整账号边界替换。

## 执行

以下命令仅在已确认的局域网项目中使用；生产写入必须获得本任务授权。
输出目录必须为仓库外全新目录，工具使用当前执行账号 SID 和 SYSTEM 限制访问。

```powershell
& '.\.venv\Scripts\python.exe' -B tools/normalize_talent_remarks.py snapshot --directory '<仓库外批次目录>'
& '.\.venv\Scripts\python.exe' -B tools/normalize_talent_remarks.py preview --directory '<仓库外批次目录>'
& '.\.venv\Scripts\python.exe' -B tools/normalize_talent_remarks.py apply --directory '<仓库外批次目录>' --sha256 '<预览计划散列>' --confirm-production-write
& '.\.venv\Scripts\python.exe' -B tools/normalize_talent_remarks.py verify --directory '<仓库外批次目录>' --sha256 '<预览计划散列>'
```

`snapshot` 在只读一致性事务中保存人才与关联表快照，另保存整库 PostgreSQL 自定义备份、恢复清单及 SHA256，并将备份完整解码到空设备验证内容。`preview` 不连接数据库。`apply` 核对目标与备份散列，每批最多 200 人，锁定人员及已有关联，比较完整快照后逐人使用保存点写入；提交前保存变更前后账本。

预览校验失败、并发变化、语种目录变化或事务内计划外变更均阻断写入。重跑依据稳定关联 ID 和账本恢复，不重复写入；准备状态的账本通过实际数据库前后快照判断是否已提交。

提交后 `verify` 使用新只读事务逐项比较已提交数据，核对人员身份数量、全部关联及未执行记录的基线。同期其他编辑单独报告，不当作工具完成的变更。

需要回滚且已获得对应操作授权时：

```powershell
& '.\.venv\Scripts\python.exe' -B tools/normalize_talent_remarks.py rollback --directory '<原批次目录>' --sha256 '<原计划散列>' --confirm-production-write
```

回滚只恢复仍与该批次写入后完整快照一致的记录，删除该批次新增关联。后续编辑会阻断对应回滚，不覆盖其他人的修改。
需要只恢复部分记录时，可增加 `--ids <人才ID> ...`，只允许指定本批账本中的人员。缺失占位词“暂时找不到”等不能作为“所在微信”值回填。

## 交付与验收

- `snapshot.json`、`production-before.dump`、`backup-toc.txt`、`backup-manifest.json`：原始数据及生产备份。
- `plan.json`、`preview-summary.json`、`validation-errors.json`：逐字段候选、原值、新值、来源及处理依据。
- `ledger.json`、`verification.json`：实际提交批次、前后快照、异常和新事务核验。
- 真实接口与页面验收报告：列表、详情、编辑回显、筛选、联系方式权限及只读浏览器请求检查。
- `final-summary.json`、`final-audit.json`、`review-items.json`：多批次账本衔接、全库最终快照核对及当前待核清单；`final-review` 保存最终当前数据的只读预览，要求剩余自动变更为零。

上述含个人资料的文件不得提交仓库。仓库中的测试只使用虚构人才和隔离 SQLite 数据库；完整运行与页面验收在本机 PC完成。

多轮最终只读核验与实际页面验收：

```powershell
& '.\.venv\Scripts\python.exe' -B tools/audit_talent_remark_result.py --directories '<第一轮目录>' '<第二轮目录>' '<最后一轮目录>'
& '.\.venv\Scripts\python.exe' -B tools/verify_talent_remark_live.py --directory '<需验收的批次目录>'
```

全库核验按批次账本重放完整快照。同期语种目录变化仅允许空的概览绑定键补齐，且必须用数据库现有概览、语种名称与别名重新唯一解析验证；名称、身份、别名或其他目录变化均导致验收失败。页面工具仅使用现有账号，在内存中生成短期令牌，禁止业务写请求，不保存令牌。
