# 资源开拓与人才总库微信账号同步

“交换账号”沿用原对接账号的单选配置；“加微账号”与人才“所在微信”支持多选及自定义。两页共用 HR1～HR6、HR1企微～HR6企微预设。人才本人的微信号与这些公司账号独立。

“所在微信”允许账号名称和“已删微信”“已删企微”并存。删除标记表示对应渠道有删友情况，不表示所有 HR 账号都失联；具体账号差异写入跟进说明。

## 保存与同步

- 首次新建/关联人才、修改交换或加微账号时，向人才账号追加去重；删除开拓账号不删除总库账号，总库账号编辑不改写开拓账号。
- 后续新增或修正渠道最后一条跟进为“（对方）已删”时，增加对应删除标记；新确认“已添加”时移除对应标记。总库主动增加/取消标记分别同步为已删/已添加。
- 仅根据 `person_id` 同步全部关联记录，不以姓名建立关联。两个渠道独立处理。普通保存不重放旧跟进，也不回填总库主动移除的账号。
- 系统联系状态保存在 `contact_state`，列表、详情及筛选使用该状态；原始跟进、申请次数、日报计数和业务日期不受系统同步影响。系统同步由审计记录操作者、来源及时间，不生成业务跟进操作。
- 开拓沿用 `revision` 防止覆盖旧记录；人才新增 `wechat_accounts_revision`，修改账号时提交读取到的版本。账号未改动时不提交账号字段。两端共用事务锁，同次保存全部成功或回滚。

## 接口兼容

开拓读写新增 `friend_accounts: string[]`，列表另返回 `friend_accounts_text`。人才读写新增 `wechat_accounts: string[]`，响应返回 `wechat_accounts_revision`；更新多值账号时将该版本作为预期值提交。每个账号最多100字符，最多100项。原 `wechat_account` 保留为兼容文本；旧字符串整体转换为一个值，不按逗号或顿号拆分。新多值的兼容文本使用顿号连接。

## 局域网迁移与验证

按 `docs/infra.md` 核对主机、项目目录、Git 提交后，在局域网 `E:\xinshi_system` 执行：

```powershell
# 先生成只读历史账号合并预览，可在结构迁移前运行。
& '.\.conda_env\python.exe' tools/migrate_talent_wechat_accounts.py
# 增量结构迁移（可重复执行），只将已有单值整体转换为数组。
& '.\.conda_env\python.exe' tools/migrate_talent_wechat_accounts.py --apply-schema
# 核查预览后，使用实际操作人的用户 ID 执行追加回填。
& '.\.conda_env\python.exe' tools/migrate_talent_wechat_accounts.py --backfill --actor-id '<实际操作人UUID>'
$env:RUN_RESOURCE_DEVELOPMENT_DB_TESTS='1'
& '.\.conda_env\python.exe' -m pytest tests/test_talent_wechat_sync.py tests/test_talent_wechat_account.py tests/test_resource_development.py tests/test_resource_follow_up.py -q
```

默认预览保存到 `.tmp/talent-wechat-accounts-preview.json`，包含人才 ID、原值、新值和来源记录 ID。历史回填只追加账号，不从旧跟进推断当前删除状态。前端使用调试机已有 Node.js，在隔离输出目录构建并执行 `tools/verify_talent_wechat_accounts_ui.py`，避免覆盖正在服务的 `frontend/dist`。需要重启后端时严格使用现有交互式计划任务与 UNC 验证流程；生产发布需单独指令。
