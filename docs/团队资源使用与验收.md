# 团队资源

团队资源入口位于「人才资源管理 → 人才总库」二级导航的「全职资源」后，地址为 `/resource-management/teams`。

## 业务规则

- 团队为独立组织档案，不进入个人列表、个人同名核重或个人人数统计。
- 简称、团队类型、资源类型必填；全称、人员、对接日期及说明可后补。
- 资源类型可多选，选择「其他」必须填写当前团队的其他说明；取消选择后保存会清除该说明。
- 对接人和跟进人均为单选，允许同一人担任。新增只能选择在职用户；已引用的停用人员可在原字段保留，也可清空或替换。
- 简介与资源情况支持多行纯文本。文本子弹窗「确定」仅回填主表单，最终点击主表单「保存」才入库。
- 简称或非空全称重名会提示已有团队，经确认后允许保存独立档案，不自动合并。
- 更新与删除校验整数版本号。编辑冲突后可读取最新记录并恢复草稿，核对后再次保存。
- 详情按需加载；列表字段设置按当前用户独立保存。删除统一通过页面级删除管理，审计在团队删除后保留。
- 登录用户可读取；写入与删除沿用 `talents:write` 或兼容的 `translators:write` 权限。
- 对接日期为纯日期，系统时间使用带时区字段，接口输出 `+08:00`，页面按UTC+8展示。

## 数据库初始化

新增表为 `resource_team`、`resource_team_audit`，显式迁移文件为 `data/migrations/20261012_resource_teams.sql`。迁移可重复执行，不接入服务启动迁移。

未初始化时，只有团队接口返回503及「模块尚未初始化」提示，不影响既有资源模块。

本机迁移入口：

```powershell
Set-Location -LiteralPath 'E:\xinshi_system'
& '.\.venv\Scripts\python.exe' tools/apply_resource_teams_migration.py
```

此入口核对PC、项目目录、项目解释器、Git提交和数据库目标，仅允许连接 `localhost` 或 `127.0.0.1`。当前日常服务数据库位于云端，执行入口会拒绝该目标。对业务库的结构迁移与发布必须获得明确指令，并遵循 `docs/infra.md` 的核对、备份与回滚要求。

## 隔离验收

先执行 `deploy/start_local.ps1 -CheckOnly` 核对本机环境，再使用项目解释器运行：

```powershell
& '.\.venv\Scripts\python.exe' tools/verify_resource_teams.py
```

脚本使用PATH中的本机PostgreSQL，创建独立临时实例和 `teams_test` 专用库，覆盖首次及重复迁移、后端回归与真实前后端浏览器交互；结束后停止专用服务。不会连接业务数据库。浏览器使用本机Edge与独立上下文，不占用3000/8000端口。

身份替身仅存在于明确设置 `TEAM_RESOURCE_QA=1` 的专用验收进程；该入口再次核对数据库主机、用户名及库名，不作为日常服务启动入口。

报告、日志和截图保存在 `.tmp/resource-teams-qa`。前端完整测试与构建在 `frontend` 目录执行 `npm.cmd test`、`npm.cmd run build`。
