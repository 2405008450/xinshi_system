# 人才概览企微大群管理

## 使用方式

人才概览按“语种/方言 → 多个企微项目大群”管理。主表默认显示总库人数、原表合计、已建/未建群数、项目群人数与最新统计日期；“字段设置”可立即显示原有来源列，设置按页面和当前用户保存。进入原表编辑模式后展示原有来源列，群相关写操作暂时隐藏。

点击语种行的展开按钮或“管理群”，可以新增群、编辑语种计划和备注。群名必须填写，未建群填写拟用名称；建群日期可以留空。每个群另有独立的计划、备注。所有表单由公共可拖拽弹窗和 AppForm 呈现，支持字段搜索、校验失败定位以及固定底部操作栏。

已建且未归档的群可以登记人数：填写统计日期和非负整数，允许零和历史补录。同日可以登记多次，最后一次登记生效；统计日期较早的补录不覆盖较新日期。最新人数与上一条有效统计比较，显示增减。未登记显示“-”，不会冒充零。

“查看详情”小窗展示完整资料、最近操作人、操作时间、人数历史和操作历史。历史支持分页。统计录错时点击“作废”，填写原因；原记录和作废人、作废时间仍可查看，当前人数自动重新计算。正确数据另行登记。

不再使用的群可以归档，退出当前汇总；勾选“显示归档群”可查看和恢复。归档、恢复、资料修改、人数登记与作废全部留痕，不提供永久删除群或直接覆盖历史人数的接口。

## 统计与溯源

- 项目群人数合计只汇总未归档的已建群各自最新有效人数，显示已登记群数/已建群数。
- 多个群的人员可能重复，统计日期也可能不同，合计为未去重人次；不计入原表合计或人才总库人数。
- 语种通过稳定的 `overview_key` 关联，群通过独立 UUID 识别，不用可修改的名称作关联键。
- 原表快照、群资料、人数记录和操作历史独立保存。标注项目语种储备查询继续使用原表口径。
- 服务端自动生成操作人、操作时间，并保留当时姓名快照；客户端不能提交这些字段。
- 群与语种管理信息分别使用修订号。保存发生冲突返回 409，表单保留草稿，用户可复制内容后显式重新加载核对。
- 业务修改与审计在同一事务提交。访问权限沿用人才概览，写入需 `talents:write` 或 `translators:write`。

## 接口

接口前缀为 `/talents/overview`。主概览的语种行增加 `wecom_summary`；原整表 PUT 请求不承载群资料。

| 路径 | 方法 | 用途 |
| --- | --- | --- |
| `/languages/{overview_key}/management` | GET / PUT | 语种计划、备注与独立修订号；尚未保存时修订号为 0 |
| `/languages/{overview_key}/groups` | GET / POST | 群列表与新增；查询 `include_archived=true` 包含归档群 |
| `/languages/{overview_key}/history` | GET | 语种管理操作历史 |
| `/groups/{group_id}` | GET / PUT | 群详情、资料编辑 |
| `/groups/{group_id}/archive` | PUT | 归档或恢复 |
| `/groups/{group_id}/counts` | GET / POST | 人数历史与新增登记 |
| `/groups/{group_id}/counts/{count_id}/void` | PUT | 作废统计，必须提供原因 |
| `/groups/{group_id}/history` | GET | 群操作历史 |

编辑、人数登记、作废、归档/恢复需提交 `expected_revision`。历史接口接收 `page`、`page_size`，默认每页 10 条，最大 100 条，返回 `items` 和 `total`。人数以统计日期及登记编号降序排列；操作历史按操作编号降序排列。

## 迁移与验证

增量迁移为 `data/migrations/20261008_talent_overview_wecom.sql`，创建四个独立表，可重复执行，不改写原表数据。局域网迁移工具 `tools/apply_talent_overview_wecom_migration.py` 会先检查主机、项目目录和数据库主机，将现有概览快照及初始表备份到仓库外 `E:\xinshi_runtime\backups`，再执行迁移。该工具拒绝连接生产地址。

当前局域网项目默认数据库配置指向生产库。此次功能验证必须在独立源码目录和临时 PostgreSQL 实例执行，不直接迁移当前业务库或发布前端。将来部署时，必须先在获授权的目标数据库执行迁移，再更新后端及前端。

`tools/verify_talent_overview_wecom_isolated.py` 仅允许在调试机 `xinshi_validation` 隔离目录运行，使用项目已有 `.conda_env\python.exe`，自行创建绑定 `127.0.0.1` 随机端口的临时 PostgreSQL，结束后停止实例。可用 `--suite backend`、`--suite frontend`、`--suite build`、`--suite ui` 选择检查。

页面验收使用真实编译页面，群相关请求桥接到隔离 FastAPI/数据库，不启动或重启业务后端。覆盖新增和编辑、人数登记和作废、历史查看、语种计划、归档恢复、并发草稿、只读权限、拖拽边界与位置复位、小屏固定底栏、字段搜索、字段设置与用户隔离。验证日志、截图和结果 JSON 留在隔离目录。

第一版不对接企微接口，不从图片导入数据。旧表需要完整 Excel 后再安排历史映射与导入，历史操作记录从功能启用后开始生成。
