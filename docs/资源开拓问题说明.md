# 资源开拓问题

本文记录聊天收录与后续任务的基础能力。讨论主题与手工新增入口由主题分类功能增量扩展，另见对应功能说明。

资源开拓页面提供“开拓日志”“每日安排”“开拓问题”三个页签。开拓问题收录系统聊天中的安排、执行、问题和想法，后续任务独立管理，不同步每日安排、个人任务或日报，不自动发送通知。

## 收录与跟进

在笔译项目聊天、标注项目聊天或内部私聊的普通文字消息操作区，点击“收录到开拓问题”，选择安排类、执行类、问题类或想法类。类别由入口带入，提出人为消息作者，来源为实际对话；这三项只读。内容默认原文，允许整理，原始消息另存快照。纯附件、已撤回消息和系统事件不能收录；附件仍在原对话查看。

同一消息、同一类别只收录一次，重复提交不会新建记录或任务。可先保存记录再添加任务，也可点击表单中的“保存后添加后续安排”，保存成功后继续安排。

每条后续任务包含安排内容、执行人、预定完成日期、实际进度、进展说明、实际完成日期和备注。内容及执行人必填，预定日期可留空。状态为未开始、进行中、已完成、已取消。首次标记完成默认填香港时间当天，可补录历史实际日期，不能填未来日期；离开已完成状态清空当前完成日期，审计保留历史变更。

来源点击后打开原对话并定位消息。来源撤回、删除、项目沟通关闭或当前用户无原对话权限时，显示提示，保留收录快照。收录后的正文和快照按开拓问题权限共享，并不授予原对话访问权。

## 权限

| 身份 | 能力 |
| --- | --- |
| 有现有开拓写入权限的人 | 从有权访问的聊天收录 |
| 提出人、收录人、当前任务执行人 | 查看关联记录，即使无原资源权限也能进入问题页签 |
| 有开拓写入权限的提出人、收录人 | 修改主体及创建、编辑、删除后续任务 |
| 当前任务执行人 | 更新本人任务状态、说明和完成日期，不修改安排内容、执行人、预定日期或备注 |
| 开拓统筹人员、管理员 | 查看和维护全部开拓问题；原私聊仍仅限双方 |
| 有写入权限的收录人、管理员 | 删除记录；代录权限不授权删除他人收录的记录 |

无资源权限的关联人员进入资源开拓后只显示开拓问题，日志和每日安排保留既有权限。任务改派后，原执行人若无其他关联身份即失去记录访问权。历史停用人员名称保留，新分配只能选择启用人员。

## 列表与并发

关键词匹配内容、备注、来源对话、提出人及任务内容、执行人、进展、备注。类别为常用条件，提出人、执行人、任务状态、预定完成日期范围在高级筛选中。组合任务条件必须匹配同一条任务，列表及总数共用查询。文本查询400ms防抖，清空立即查询，旧请求取消并保护响应顺序。

字段设置按模块及当前用户保存在 localStorage，允许全部取消并支持恢复默认。详情使用左向 Popover，长内容内部滚动。删除管理提供单条确认、多条输入“删除”的强确认及部分失败保留选择；删除成功清理详情，末页自动回退。

修改主体、增删改任务和删除记录均提交**主体修订号 `revision`**。任一任务写入都会增加主体修订号；任务自身也保存修订号用于审计。服务器返回409时表单保留草稿，并提供明确的重新加载操作，不静默覆盖。

## 接口

所有接口位于 `/resource-development/issues`，独立于旧资源路由权限依赖；接口先验证启用的登录用户，再执行逐记录授权。

| 方法及路径 | 用途 |
| --- | --- |
| `GET /access` | 只读结构探测及 `ready/can_enter/can_collect/can_manage/can_resource/user_id` |
| `GET /options` | 能力及启用内部人员选项 |
| `GET /source/{message_id}` | 收录前校验实际聊天及消息，返回只读来源快照 |
| `GET /` | `keyword/category/proposer_id/executor_id/status/planned_start/planned_end/skip/limit`，返回 `items/total` |
| `POST /` | `source_message_id/category/content/remarks`；响应包含 `already_collected` |
| `GET /{id}` | 完整主体、任务及可操作能力 |
| `GET /{id}/source` | 再检查原对话访问，返回 `available` 及来源或不可访问原因 |
| `PUT /{id}` | `revision/content/remarks`，不接受客户端伪造来源或提出人 |
| `DELETE /{id}?revision=...` | 删除主体及任务，保留删除前审计 |
| `POST /{id}/tasks` | 新任务，必传主体 `revision/content/executor_id` |
| `PATCH /{id}/tasks/{task_id}` | 差量任务更新，必传主体 `revision`；执行人限进度字段 |
| `DELETE /{id}/tasks/{task_id}?revision=...` | 删除任务并增加主体修订号 |

类别协议值为 `arrangement/execution/problem/idea`，任务状态为 `pending/in_progress/completed/cancelled`。日期字段为 `YYYY-MM-DD`；新增创建/更新时间使用 `timestamptz`，生成时明确UTC+8，响应携带 `+08:00`。审计沿用已确认按UTC+8本地时间存储的开拓审计字段，不调整历史时间。

## 迁移与隔离验收

迁移文件：`data/migrations/20261012_resource_development_issues.sql`。新增独立主体表与任务表，来源消息ID不设级联删除外键，保留来源快照。迁移可重复执行，不回填历史聊天。服务启动不会执行此迁移；未迁移时能力接口返回 `ready=false`，页面显示提示，原日志、每日安排仍可使用。结构探测缓存最多5秒，授权迁移后无需依靠启动建表。

**日常本机服务连接云端业务数据库，本次实现未授权或执行业务库迁移、发布、重启。** 上线需按 `docs/infra.md` 单独核对主机、目录、提交及数据库，备份并取得明确迁移指令。

使用叠加主题分类功能的代码时，还需在基础迁移之后应用 `data/migrations/20261012_chat_topics.sql`。隔离验收脚本已兼容这一顺序；基础收录验收不等于主题分类全部能力的验收。

本机验收使用固定项目虚拟环境及随机本机端口的临时独立PostgreSQL；脚本检查主机PC、项目目录、解释器和专用数据库身份，不执行主应用startup、不读取UNC业务文件。身份替身仅供验收入口，业务授权使用真实权限判断。结束后自动停止临时前后端与数据库。
