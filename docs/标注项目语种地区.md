# 标注项目语种地区

## 录入与查看

- 地区要求归属于当前订单的语言项，不修改共享语种目录。
- 新增、编辑选择语种后，可填写城市、区县、街道，并添加多条地区；三项均选填，允许只填其中一项。
- 每项最多 100 字，保存时去除首尾空白并忽略全空行。删除全部地区后保存会清空该语言项的地区。
- 列表和详情点击语种，在同一小窗查看地区和人才储备；多语种在窗内切换。
- 人才储备仍按语种统计，未经地区筛选；储备加载失败不影响查看地区。
- 翻译方向的地区属于整个方向，不区分源语种与目标语种两端。

## 下级订单与兼容性

- 自动拆单仍按语种方向计算。一个语种的多个地区不会生成多个子订单。
- 新建子订单、三级订单时，复制所选来源语言项的地区；复制后独立维护，上级修改不覆盖下级，已有下级不自动补写。
- 手动新建下级订单可在保存前调整地区，修改复制来源方向时重新带入该来源的地区。
- 三级订单语种仍只读，地区可独立编辑；上级强制同步语种时保留三级订单本地地区。
- 原项目级“语言地区”和三级订单“片区”维持原义，不自动解析或迁移其历史文本。
- API 的 `language_items[].regions` 为数组，每项包含可空的 `city`、`district`、`street`。更新省略 `regions` 保留原值，显式 `[]` 清空。

## 主列表地区展示与检索

- 主列表将原“语言地区”和“片区”两个列入口收拢为“地区”列，默认显示城市。点击表头层级下拉可改为区县或街道；选择按页面和当前用户保存，刷新后保留，切换不触发业务查询。
- 同一级地区名称去重后展示第一个及其余数量；点击摘要打开“地区详情”小窗，按语种列出全部城市、区县和街道。小窗内部滚动，不改变主表格高度。
- 只有区县或街道时不会猜测城市。没有结构化地区的旧记录以“原地区”摘要展示，原语言地区、原片区在小窗中按原文保留。
- 列表“地区”漏斗集中提供城市、区县、街道及原地区条件。文本输入遵循 400ms 防抖、回车查询、清空立即查询、取消旧请求及旧响应保护；新查询回到第一页。
- 城市、区县、街道组合须命中同一条地区；同时筛选语种时须属于该语言项。列表、总数和导出复用查询条件。
- 新筛选通过 `field_filters` 中的 `region_city`、`region_district`、`region_street` 传递，使用 `contains`。OpenAPI 的列表接口声明 `x-annotation-region-filters` 后才显示相应筛选，避免对旧后端提交不支持的参数；旧地区筛选继续可用。
- 历史字段显示配置中的 `languageRegion`、`areaLabels` 自动映射为一个地区列，其他列选择保留；字段设置仍允许全部取消和恢复默认。查询重置不会清除展示层级偏好。
- 本轮仅调整主列表展示与检索，不更改新增、编辑弹窗或订单片区关联，不新增数据库迁移。

## 数据库与启用顺序

增量迁移：`data/migrations/20261017_annotation_language_regions.sql`。

迁移新增 `annotation_project_language_item.regions` JSONB 列，默认空数组，并约束为数组类型；支持重复执行，不推测历史地区归属。

本次仅在本机临时 PostgreSQL 实例执行迁移验证，没有修改共享业务数据库。实际启用必须按 `docs/infra.md` 与根目录 `AGENTS.md`，在取得对应环境授权、核对主机、目录、Git 提交及目标数据库后，先执行迁移，再启动新版后端。启动沿用 `deploy/start_local.ps1`，常驻服务保持 `LOCAL_SCHEMA_MIGRATIONS_ENABLED` 关闭。

前端通过 OpenAPI 检测后端是否声明语言项地区字段；旧后端显示兼容提示并隐藏地区录入，不向旧接口提交地区，避免出现填写后被忽略的情况。
