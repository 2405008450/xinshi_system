# Translation Workflow Refactoring & UI Optimization Plan

This plan aims to implement the optimizations requested for the translation project system, specifically focusing on workflow decoupling, code modularity, and user experience enhancements for form interactions.

## User Review Required

> [!IMPORTANT]
> The backend `WorkflowStateResponse` will be modified to include `effective_stages` dynamically, ensuring the frontend is fully decoupled from workflow branching logic. Please confirm if altering the `WorkflowStateResponse` schema in `workflow_schemas.py` is acceptable.
> 
> Additionally, `TranslationProjects.vue` (currently >2500 lines) will be split into multiple standard components. We will create a `components/` subfolder in your `translation/` directory for this purpose.

## Proposed Changes

---

### Backend: Workflow Engine Decoupling

By having the backend dictate the available stages, we decouple the frontend from business logic, making future additions of roles (e.g., Corpus Manager) seamless.

#### [MODIFY] `workflow_schemas.py`
- Add `effective_stages: list[dict]` to `WorkflowStateResponse`.
- Add an endpoint schema for querying base workflow configurations if needed.

#### [MODIFY] `routers/workflow.py`
- Update `_build_state_response` to dynamically calculate and append `effective_stages` based on the instance's `difficulty` and `file_editable` fields.
- Expose a `GET /workflow/config` endpoint returning `ALL_STAGES`.

---

### Frontend: UI Optimization - `ProjectDetails.vue`

The overwhelming 30-field form will be replaced with an organized, categorized layout (Tabs or Collapses) enclosed within a Drawer or categorized Dialog for an immersive experience.

#### [MODIFY] `frontend/src/views/project/translation/ProjectDetails.vue`
- Change `<el-dialog>` for Add/Edit Project to use `<el-tabs>`.
  - **Tab 1: 基础信息 (Basic Info):** OrderNo, ProjectName, Client, Dates, Priority.
  - **Tab 2: 分配与预估 (Assignment):** Translator ID, WordCount, Language Pair, Network Paths.
  - **Tab 3: 执行进度 (Progress Tracker):** All progress inputs (Review, QC, Layout) changed to `el-slider` (0-100) or structured tags for better data standardization where acceptable, or simply grouped neatly.
  - **Tab 4: 子订单 (Sub Orders):** Move the sub-order management table directly into its own tab rather than tagging it below the massive form.
- The same tabbed layout logic will be applied to the `subOrderDialogVisible` modal.

---

### Frontend: Code Refactoring - `TranslationProjects.vue`

Given its monolithic nature (2500+ lines), we will break `TranslationProjects.vue` into logically separated components and composables.

#### [NEW] `frontend/src/composables/useWorkflow.js`
- Extract all API calls and state management related to `getWorkflowStateAPI`, `transitionWorkflowAPI`, `rollbackWorkflowAPI`, etc.

#### [NEW] `frontend/src/composables/useEntityPicker.js`
- Extract the picker logic (`entityPickerVisible`, `entityPickerFilters`, pagination, searching).

#### [NEW] `frontend/src/views/project/translation/components/WorkflowStageCard.vue`
- House the core interaction area where users click "Submit", set difficulty, assign next personnel, and type handover notes.

#### [NEW] `frontend/src/views/project/translation/components/ProjectFilesTab.vue`
- Componentize the files table, file editing dialog, and network path copy interactions.

#### [NEW] `frontend/src/views/project/translation/components/MyTasksTab.vue`
- Extract the "待我处理" tasks table. 

#### [MODIFY] `frontend/src/views/project/translation/TranslationProjects.vue`
- Remove all local state now handled by composables and components.
- Import and structure the new child components.
- Maintain top-level reactive state (like `currentProject`) injected/provided to children.

## Open Questions

> [!WARNING]
> Componentizing `TranslationProjects.vue` is a significant structural shift. It relies heavily on Vue's reactivity (`ref`, `reactive`). I plan to use `Provide/Inject` or simple prop drilling for the `currentProject` state so sub-components can access it transparently. Is this architecture acceptable to you?
