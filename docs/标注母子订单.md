# 标注项目母子订单

母订单关联派发任务的合作方，沿用客户体系。子订单按语种、批次或任务类型拆分，仅支持一层；同一语种可建立多个子订单。

## 使用方式

- 标注项目主列表默认查询母订单；展开后按需显示前 10 个子订单及状态数量，完整记录进入“子订单管理”。
- 母订单保存后，编辑窗口的“子订单”页签可单条新增或批量新增。批量创建先预览任务名称、类型、语种、负责人及提交时间，每批最多 100 条。
- 子订单管理复用标注项目编辑器，独立维护人员、价格、试标、进度、安排、账号分配、资料、通知和聊天。子订单详情、表单及执行页面提供母订单上下文。
- “分拆子订单”按母订单全部现有单语种/语言方向生成预览；“新增/批量新增子订单”允许增加方向或同语种批次，默认保留首个方向的源语种和目标语种。
- 创建时复制母订单业务快照：客户及联系人、客户经理、客户单号、项目名称、类型、任务、优先级、状态、需求量、地区、派发及提交时间、咨询及确认时间、邮件主题前缀、路径、项目自定义字段和内部负责人；之后独立维护，母订单修改不再覆盖子订单。
- 每行可选择“复制来源方向”：客户报价复制公共价格及该方向价格，保持金额、币种、单位等并改为子订单方向；人员安排复制公共人员及该方向人员，重新关联子订单语种，保留人员单价及动态字段值。其他方向明细不混入当前子单。
- 复制项目、报价、合同资料的全部版本，子订单具有独立文件/版本记录；不可变上传内容可共用，删除最后一个引用后才清理文件。聊天、通知、试标记录、进度历史、账号分配、工作台任务和操作审计不复制；新订单从自身状态建立新的历史。
- 历史子订单不自动重新复制，避免覆盖已经人工维护的内容。
- 母订单仍可执行公共任务。子订单状态数量不包含母订单自身进度，不自动改变总体状态，不合并自由文本需求量或金额。

## API

原标注项目列表、分页及总数接口增加 `order_scope=all|parent|child`、`parent_project_id`，默认保持 `all` 以兼容既有调用。

- `GET /projects/annotation/{id}/children`：分页查询子订单，默认 10 条。
- `POST /projects/annotation/{id}/children`：单条创建，内容为标注项目创建对象。
- `POST /projects/annotation/{id}/children/batch`：整批创建，内容为 `{items: [...]}`。

创建接口要求 `X-Idempotency-Key`。同一批次重试返回原记录，内容改变应使用新键；整批校验或保存失败时回滚全部订单、编号预留及进度记录。编辑继续携带 `expected_updated_at`；创建预览携带 `expected_parent_updated_at`，母订单被其他人修改后必须重新加载预览。幂等重试仍返回原有子订单，不因母订单后续修改重复创建。

子订单号自动生成，例如 `AP-261006-001-S001`。序号和编号永久保留，删除后不复用；母订单历史改号也不重置子订单序号。存在子订单时禁止修改母订单编号，子订单禁止手动改号。母订单必须先处理全部子订单才能删除。

## 迁移与验证

执行 `data/migrations/20261014_add_annotation_child_orders.sql`；资料复制还需执行 `data/migrations/20261015_annotation_material_shared_versions.sql`，解除上传对象的一对一版本限制并建立引用索引。仅调整字段、约束和索引；历史记录的母订单关联保持为空，不自动拆分。迁移可重复执行。

局域网调试机使用 `E:\xinshi_system\.conda_env\python.exe`。隔离验证目录中的 `tools/verify_annotation_child_orders_postgres.py` 启动临时 PostgreSQL 实例，验证迁移、事务、编号并发、幂等、快照复制及独立维护；`tools/verify_annotation_child_orders_ui.py` 对真实构建页面使用模拟业务接口验收，不写业务库。生产环境发布需另行授权。
