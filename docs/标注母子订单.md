# 标注项目三级订单

订单关联派发任务的合作方，沿用客户体系。子订单按语种、批次或任务类型拆分，子订单下面可按片区建立三级订单，最多三级；同一语种或片区可建立多个批次。三级订单语种固定继承所属子订单。

## 使用方式

- 标注项目主列表默认查询订单；展开后按需显示前 10 个子订单及状态数量，完整记录进入“子订单管理”。
- 订单保存后，编辑窗口的“子订单”页签可单条新增或批量新增。批量创建先预览任务名称、类型、语种、负责人及提交时间，每批最多 100 条。
- 子订单管理复用标注项目编辑器，独立维护人员、价格、试标、进度、安排、账号分配、资料、通知和聊天。子订单详情、表单及执行页面提供订单上下文。
- “分拆子订单”按订单全部现有单语种/语言方向生成预览；“新增/批量新增子订单”允许增加方向或同语种批次，默认保留首个方向的源语种和目标语种。
- 创建下级时复制直属上级业务信息：客户及联系人、客户经理、客户单号、项目名称、类型、任务、优先级、状态、需求量、地区、派发及提交时间、咨询及确认时间、邮件主题前缀、路径、项目自定义字段和内部负责人；新建下级的字段默认继承上级；用户修改或清空后转为独立维护，上级修改只更新仍在继承的字段，并逐层传递。报价和人员安排分别按整组保护，自定义字段逐项保护。编辑窗口提供“恢复继承”，勾选字段并保存后立即恢复上级当前值。
- 每行可选择“复制来源方向”：客户报价复制公共价格及该方向价格，保持金额、币种、单位等并改为子订单方向；人员安排复制公共人员及该方向人员，重新关联子订单语种，保留人员单价及动态字段值。其他方向明细不混入当前子单。
- 复制项目、报价、合同资料的全部版本，子订单具有独立文件/版本记录；不可变上传内容可共用，删除最后一个引用后才清理文件。聊天、通知、试标记录、进度历史、账号分配、工作台任务和操作审计不复制；新订单从自身状态建立新的历史。
- 历史子订单不自动重新复制，继承元数据为空表示所有字段独立维护；主动恢复指定字段后，只同步这些字段，未来新增字段仍默认独立，避免覆盖人工维护的内容。
- 订单只有一个方向时不自动生成；两个及以上方向在新增或编辑保存时自动补齐缺失子订单，每个子订单必须且只能绑定一个方向。未填写目标语种的单语种也算一个方向，反向语言对分别计算。
- 已有同方向子订单及多批次不重新创建，仍继承的普通字段按规则更新；删除或改方向后，下次保存多方向订单补回缺失方向，新编号不复用。删减订单方向不会删除子订单，详情提示额外方向及历史非单方向子订单。
- 人员单价随表单在项目事务内保存，保证自动子订单复制本次提交的单价；旧接口不提交单价时保持原值，显式 `rate: null` 删除订单自身单价。
- 订单仍可执行公共任务。子订单状态数量不包含订单自身进度，不自动改变总体状态，不合并自由文本需求量或金额。

## API

原标注项目列表、分页及总数接口增加 `order_scope=all|parent|child|grandchild`、`parent_project_id`、重复参数 `area_ids`，默认保持 `all` 以兼容既有调用。

- `GET /projects/annotation/{id}/children`：分页查询直属下级，订单返回子订单、子订单返回三级订单；默认 10 条，支持 `area_ids` 过滤。
- `POST /projects/annotation/{id}/children`：单条创建，内容为标注项目创建对象。
- `POST /projects/annotation/{id}/children/batch`：整批创建，内容为 `{items: [...]}`。

创建接口要求 `X-Idempotency-Key`。同一批次重试返回原记录，内容改变应使用新键；整批校验或保存失败时回滚全部订单、编号预留及进度记录。编辑继续携带 `expected_updated_at`；创建预览携带 `expected_parent_updated_at`，订单被其他人修改后必须重新加载预览。幂等重试仍返回原有子订单，不因订单后续修改重复创建。

子订单号自动生成，例如 `AP-261006-001-S001`。序号和编号永久保留，删除后不复用；订单历史改号也不重置子订单序号。存在子订单时禁止修改订单编号，子订单禁止手动改号。任何有下级的订单都必须先处理全部直属下级才能删除。三级订单号沿用直属上级编号加序号，例如 `AP-261006-001.001.001`，也永久保留且不允许手动改号。

创建与更新响应增加 `auto_created_child_count`，仅表示本次保存生成数量；详情增加 `direction_summary`，返回是否启用自动生成、方向数量、缺失方向、额外方向及历史非单方向子订单号。订单保存及全部自动子订单在同一事务提交，失败整次回滚。


## 片区、继承和页面

- 新增 `GET/POST /projects/annotation/areas`，标注模块共用片区目录。名称做 Unicode NFKC、首尾去空格和大小写归一，重复新增返回已有项；标准化后名称不超过 100 字符。
- 新增及编辑三级订单必须提交 `area_id`，订单、子订单不可直接设置片区，片区列汇总其下级片区。片区筛选支持多选 OR，与其他条件 AND 组合；列表、总数、下级分页和导出沿用同一片区条件。
- 订单、子订单、三级订单复用同一表格和列配置，三级按需展开，保留固定的详情与操作列。业务字段可自由隐藏；三级订单管理复用子订单页面，URL 查询参数 `orderScope=grandchild`。
- 响应包含 `order_level`（订单 0、子订单 1、三级订单 2）、`area_id`、`area_labels`、`inheritance_overrides`。编辑新增 `restore_inheritance`，值为业务字段的 snake_case 键；自定义字段为 `custom:<字段UUID>`。
- `inheritance_overrides=NULL` 是历史独立维护；新建订单保存独立字段列表。历史订单恢复部分字段后内部使用 `*` 及 `inherit:<字段键>`，保证未来新增字段仍独立维护。前端只展示中文业务名称。
- 子订单改语种会同步三级订单，三级订单的语种关联报价、人员若已独立维护则阻止改动并提示先恢复继承或处理关联；失败回滚整次保存。
- 表单、快捷文本、状态、优先级、负责人、人员单价和客户经理交接入口使用同一继承服务。同步产生各订单自己的版本及状态/负责人记录，不复制聊天、执行历史或账号分配。
- 项目 API 的业务时间返回 `+08:00`，旧无时区业务表继续按已确认的香港本地时间存储。没有对历史数据统一加八小时。

## 历史方向补建

使用 `tools/backfill_annotation_direction_children.py`，覆盖所有状态的多方向订单。默认仅预览并输出 JSON 报告，不修改业务记录；应用逐订单事务并重新检查已有方向，失败不影响其他订单，重复运行不重复生成。历史非单方向子订单保留原数据并报告异常，不当作唯一方向覆盖，不迁移执行记录。

在本机项目目录运行 `.venv\Scripts\python.exe tools\backfill_annotation_direction_children.py --report .tmp\annotation-direction-preview.json`。检查报告后，用 `--apply --expected-host PC --expected-commit <当前完整Git提交> --report .tmp\annotation-direction-applied.json` 应用；工具核对主机、项目路径及提交信息，报告逐项保存。云端执行需另行明确发布授权，并先备份数据库、保存预览报告。

## 迁移与验证

执行 `data/migrations/20261014_add_annotation_child_orders.sql`；资料复制还需执行 `data/migrations/20261015_annotation_material_shared_versions.sql`，解除上传对象的一对一版本限制并建立引用索引。仅调整字段、约束和索引；历史记录的订单关联保持为空，不自动拆分。迁移可重复执行。

本机 PC 使用 `E:\xinshi_system\.venv\Scripts\python.exe`。隔离验证目录中的 `tools/verify_annotation_child_orders_postgres.py` 启动临时 PostgreSQL 实例，验证迁移、事务、编号并发、幂等、快照复制及独立维护；`tools/verify_annotation_child_orders_ui.py` 对真实构建页面使用模拟业务接口验收，不写业务库。生产环境发布需另行授权。

三级订单另需执行 `data/migrations/20261017_annotation_grandchild_inheritance.sql`，只新增片区表、关联、索引及继承元数据，不修改历史订单内容；服务启动不得自动应用。当前业务库的迁移和发布需要单独明确授权。

本机隔离验证：`.venv\Scripts\python.exe tools\verify_annotation_grandchild_orders_postgres.py` 在 `.tmp` 启动临时 PostgreSQL；前端构建后运行 `.venv\Scripts\python.exe tools\verify_annotation_grandchild_orders_ui.py`，使用真实浏览器和模拟 API，不连接业务库。
