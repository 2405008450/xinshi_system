# 项目须知

笔译、口译、招聘项目分别提供独立的须知知识库，入口为原项目管理页面的“笔译须知”“口译须知”“招聘须知”页签。首次使用没有预置栏目；具有 `projects:write` 权限的用户通过“栏目管理”建立栏目。`projects:read` 用户可阅读、搜索和下载附件。

支持两级栏目、仅分组栏目、拖动调整栏目结构、富文本正文、栏目及正文搜索、附件上传下载和删除。三个板块的栏目、正文、搜索结果与附件互相隔离，原标注须知继续使用原接口和数据。

## 接口和导航

- `/project-notices/{module}`：`module` 仅允许 `translation`、`interpretation`、`recruitment`。
- `GET /tree`、`GET /search?keyword=…&skip=0&limit=20`。
- `POST /sections`、`GET/PATCH/DELETE /sections/{id}`、`PUT /sections/reorder`。
- `PUT /sections/{id}/content`；正文和结构修改使用 `expected_updated_at`、`expected_structure_updated_at` 防止覆盖其他人的修改，版本过期返回 409。
- `GET/POST /sections/{id}/attachments`、`GET/DELETE /sections/{id}/attachments/{attachment_id}`。
- 页面使用原地址加 `?section=notices&noticeSectionId={id}`，支持直接链接、刷新及前进后退。项目列表与须知切换保留当前列表筛选、分页。

## 数据库与附件

数据库升级脚本为 `data/migrations/20261018_project_notices.sql`，创建 `project_notice_section`、`project_notice_attachment`。脚本可重复执行，不导入标注内容，不初始化业务栏目。请求只检查结构，不自动建表；结构未就绪返回 503，并在页面显示原因。

脚本交付不代表正式库迁移授权。当前本机常驻服务连接云端数据库；只有取得明确数据库升级指令，核对主机、目录、Git 提交、目标数据库并备份后，才可执行正式迁移。服务必须保持 `LOCAL_SCHEMA_MIGRATIONS_ENABLED=false`。

`PROJECT_NOTICE_UPLOAD_DIR` 可配置附件根目录，默认 `data/project_notice_uploads`；三个板块分别使用其下的独立子目录。附件根目录不应由静态服务直接暴露，下载通过鉴权 API。允许格式与标注须知一致，单文件最多 20MB、每栏目最多 50 个附件。栏目软删除后其正文及附件不可访问，不物理清除附件文件。

新时间字段使用 `timestamptz`，接口统一输出 `+08:00`，页面按 UTC+8 显示，并保留版本字段的微秒精度。

## 本机隔离验收

先执行前端构建，然后从项目根目录运行：

```powershell
E:\xinshi_system\.venv\Scripts\python.exe tools/verify_annotation_notices.py --projects --ui
```

验收入口核对主机和项目目录，创建临时本机 PostgreSQL 与独立上传目录，禁止回退到业务库。后端测试包含原标注须知回归；浏览器使用真实静态构建和真实须知 API，项目列表使用固定隔离样例，同时回归原标注须知操作。报告和截图位于 `.tmp/project-notices-qa/`。只运行浏览器验收可使用 `--projects --ui-only`。
