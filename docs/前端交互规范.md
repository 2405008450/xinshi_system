# 前端交互规范

## 时间展示与查询

所有业务时间标记和日期时间展示固定使用 UTC+8（北京时间），不随浏览器系统时区变化。新增或修改时间展示、日期筛选、日报、日志查看和导出功能时，必须遵循 [项目时间与日志时区规范](时间与日志时区规范.md)，确认接口偏移、历史无时区值语义及跨日边界，并复用公共格式化能力。

## 新增/编辑表单的首错定位与字段搜索

适用于“新咨询管理、笔译项目、口译项目、标注项目、招聘项目、稿件安排、客户信息、资源需求管理、人才资源库”等包含新增或编辑长表单的业务板块。后续新增同类板块也必须遵循本节。

### 必填校验失败后的定位

- 新增、编辑及其他需要整表校验的表单必须使用 `frontend/src/components/common/AppForm.vue`，不得直接使用 `el-form`。
- 保存或提交触发 `validate()` 后，只要存在校验失败项，公共表单会自动展开错误字段所在的标签页和折叠面板，把表单正文滚动到第一个错误项并聚焦其可编辑控件；底部操作栏必须保持可见。
- 业务页面不得再用 `querySelector('.is-error')`、`scrollIntoView()`、定时器或硬编码页签重复实现首错定位。新增字段只要正确声明 `el-form-item` 的 `prop` 与 `rules`，就应自动获得该能力。
- 动态字段的 `prop` 必须与当前可见字段及校验规则一致。字段隐藏或业务类型切换后，旧规则不得继续阻断提交。
- 无法直接表达为 Element Plus `rules` 的跨行、跨字段业务校验，也不能只弹出提示。优先改造成表单规则；确需保留业务校验时，必须调用公共字段定位能力，将用户带到对应字段。
- “保存草稿”若按业务定义允许不完整数据，可以不触发必填校验；“确认、发送、提交”等会改变业务状态的入口必须完成校验和首错定位。

### 字段名搜索

- 新增/编辑长弹窗的标题栏统一使用 `frontend/src/components/common/DialogFieldSearchHeader.vue`，并通过 `frontend/src/composables/useDialogFieldSearch.js` 对当前表单 DOM 自动建索引。
- 搜索根节点必须覆盖完整的新增/编辑正文。普通字段只需使用带明确 `label` 的 `el-form-item`，新增字段会自动进入搜索结果，禁止另建手写字段清单同步维护。
- 非 `el-form-item` 的复合编辑区需要在可定位的最小容器上设置 `data-dialog-field-search-label="字段名称"`；需要兼容俗称时可设置 `data-dialog-field-search-aliases="别名1,别名2"`。
- 重复明细需要在卡片容器上添加 `data-dialog-field-search-group`，并在组标题上添加 `data-dialog-field-search-group-title`，搜索结果会显示分组并按出现顺序区分同名字段。
- 选择搜索结果后，公共能力必须自动展开所在标签页/折叠区、滚动到字段、显示短暂高亮并聚焦可编辑控件。只读字段允许定位和高亮，不强制获得输入焦点。
- 条件未满足而未渲染的字段不应伪装为可搜索；应先定位控制该条件的开关，或仅在字段实际出现后纳入索引。
- 搜索只在用户输入时读取当前 DOM，不缓存静态字段清单，确保动态增删行、业务类型切换和后续新增字段能够同步生效。

### 开发与回归验收

1. 在新增态和编辑态分别滚动到表单底部，清空第一个必填字段后点击保存/提交，确认自动回到首错、错误文案可见且控件获得焦点。
2. 必填字段位于非当前标签页或已收起折叠区时，确认页签/折叠区会先自动打开再定位。
3. 用字段全名和部分名称搜索顶部、中部、底部字段；重复明细应能区分所属分组。
4. 临时新增一个普通 `el-form-item` 后，不修改任何搜索清单即可搜到并定位；非标准复合字段按约定添加 data 属性后也应可定位。
5. 验证新增字段的 `prop`、规则、错误文案、搜索名称和键盘焦点，确认隐藏字段不会阻断提交。
6. 桌面与小屏均验证：搜索框不挤压关闭按钮，定位过程只滚动正文，固定底部操作栏不移动。
7. 当前九个常用板块的静态回归由 `frontend/tests/formInteractionRegression.test.mjs` 覆盖；修改公共能力或任一板块表单后必须执行前端完整测试与构建。

## 列表删除管理

适用于订单、项目、账号、人才等业务对象的主列表。表单内部动态明细行、平台管理等局部子资源不在此规范范围内。

### 入口与默认状态

- 删除能力统一收敛到列表标题操作区的“删除管理”，位置与“新增”“字段设置”等页面级操作相邻。
- 优先复用 `frontend/src/components/common/BatchDeleteToolbar.vue` 和 `frontend/src/composables/useBatchDelete.js`，避免各页面重复实现不同交互。
- 默认不显示表格勾选列，逐条操作列不得放置独立“删除”按钮。
- 点击“删除管理”后进入删除模式，显示勾选列、删除模式标识、已选数量、“退出”和“删除所选”。未选中记录时禁止提交删除。
- 删除模式下隐藏逐条操作列以及新增、批量编辑等可能造成模式冲突的入口；“查看详情”等只读入口可以保留。

### 确认与执行

- 选择一条记录时使用普通二次确认，并显示可识别的业务名称或编号。
- 选择多条记录时使用加强确认，例如要求输入“删除”，同时提示数量、部分记录名称和操作不可恢复。
- 批量删除应独立处理每条记录，汇总成功与失败结果；单条失败不得中断其余记录。
- 删除失败的记录应在刷新后恢复选中，并展示可理解的具体失败原因。
- 删除成功后清除该记录的详情、履历等前端缓存，并刷新列表与总数。
- 删除导致当前页超过末页时，自动回退到最后一个有效页；分页切换时退出删除模式并清空选择。

### 验收清单

1. 默认无勾选列，逐条操作栏无删除按钮。
2. 进入和退出删除模式时，选择状态及冲突操作入口正确切换。
3. 单条删除使用二次确认，多条删除使用加强确认。
4. 全部成功、部分失败和全部失败时，提示与选中状态准确。
5. 删除末页最后一条记录后自动回到有效页码。
6. 再次打开详情时不会展示已删除记录的旧缓存。

## 沟通窗口

适用于标注项目和笔译项目的全局浮动“沟通”窗口。收藏夹、项目行操作和通知打开的是同一套窗口。

### 尺寸与布局

- 每个沟通窗口有小、中、大三档。小档保持 420×640；中档为 760×680；大档为 `min(1180px, 94vw)` × `min(880px, 92vh)`。三档都限制在视口内，切换后重新约束位置，不能把标题栏拖出屏幕。
- 标题栏使用公共 `ChatWindowStateMenu` 提供“窗口状态”菜单，直接选择小窗、中窗、大窗、全屏聊天、固定小窗和会话工作区，避免通过单字循环猜测下一档。双击标题栏空白处仍可在小档和中档之间切换。
- 系统右上角提供“聊天”入口，可在没有已打开会话时直接进入大屏；已有会话及关注项目显示在左侧。重复点击只恢复大屏，不反向切换状态。
- 大屏提供“固定小窗”：仅显示当前会话的小窗，不把其他会话一起铺开。其他会话、草稿和附件保留在原组件中，可再次从右上角进入大屏切换。还原大屏时恢复进入前的窗口最小化状态，大屏中新开的会话默认收起。固定小窗可拖动、最小化，跨业务页面保留；普通业务弹窗打开时调整其层级，允许焦点在表单与固定聊天输入区之间切换，普通表单的其余焦点约束保持不变。
- 尺寸按钮右侧提供“最大化”（全屏沟通）。点击后覆盖整个页面视口，左侧为贯穿全高的会话列表（项目头像、名称、订单号、未读标记和搜索），右侧为群聊标题、消息区与底部输入区。再点击“还原”回到最大化前的独立窗口或工作区尺寸、位置；切换过程中复用原聊天组件，保留草稿、引用与附件。全屏时隐藏尺寸切换按钮，窗口不允许拖动；视口变化时同步更新聊天内容区域。最小化后通过底部“沟通”恢复全屏。视口宽度小于 768px 时不显示最大化按钮，沿用单会话布局。
- 尺寸按“当前用户 + 窗口类型（标注/笔译）”写入 `localStorage`，键名形如 `xinshi.chatDock.{userId}`。新开的同类窗口沿用上次档位。
- 视口宽度小于 768px 时仍只保留一个近全屏窗口，不显示尺寸按钮和布局按钮。
- 标题栏提供布局开关，在独立浮窗和会话工作区之间切换，选择同样按用户持久化。工作区默认中档，可切换到大档，并可拖动。
- 工作区左侧是会话列表，宽约 240px，包含当前已打开的沟通和已关注的标注项目，显示项目名、订单号、类型和未读数。顶部用“消息 / 未读”切换，并提供会话搜索。窗口宽度小于约 640px 时，左栏收起，由标题栏的“会话”按钮展开。
- 右侧直接复用现有聊天组件，并用 `v-show` 保留未选中的会话，避免草稿、滚动位置和实时订阅丢失。点击已关注但尚未打开的项目会打开该会话。
- 工作区最小化后，底部任务条只保留一个“沟通”入口，并显示各会话未读合计。已关注项目和未读数由收藏夹与工作区共用同一份轮询和实时刷新。

### 聊天记录

- 标题栏或聊天工具栏的搜索入口打开“聊天记录”面板。大档与聊天区并排，小档和中档覆盖在聊天区之上，不改变窗口尺寸。
- 面板提供关键词、发送人、日期和只看收藏，并用“全部 / 图片 / 链接 / 文件”分类。笔译群聊没有文件上传，因此不显示“文件”。
- 关键词搜索遵循列表搜索框规则：停止输入 400ms 后查询，回车和“查询”立即查询，清空后立即恢复，取消上一条未完成请求，并用请求序号避免旧结果覆盖新结果。切换分类或修改条件后从第一页重新加载，滚动到底继续加载。
- 图片以缩略图展示并可预览，链接可打开，文件可下载。每一项都可以定位回原消息并短暂高亮。笔译聊天定位时加载目标附近的消息，并提供“返回最新消息”。
- 已撤回消息及其附件不进入检索结果。

### 验收清单

1. 三档尺寸可以切换，拖动后不超出视口，刷新后仍记住档位；窄屏仍是单窗口。
2. 独立窗口和工作区切换后，草稿、滚动位置和未读数仍在；非当前会话收到新消息时未读数增加。
3. 四个分类的结果、预览、下载、打开链接和定位高亮可用；快速切换分类不会被旧响应覆盖。
4. 标注群聊和笔译群聊各验证一遍。
